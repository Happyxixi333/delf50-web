# DELF50 Web

A1+ → DELF B1 的 50 天网页备考训练系统。

## 当前版本

当前生产版本采用三层版本管理：

- App：`1.7.2`
- State Schema：`2`
- Teaching Content：`1.7.0`

生产地址：`https://delf50-mvp.vercel.app`

这意味着 V1.7.2 本轮只升级应用与学习状态兼容架构，教学内容、50 天课程规划和题库内容仍保持 Content `1.7.0`，不会因为架构升级而重新计算或清空已有学习进度。

## V1.7 → V1.7.2 演进

V1.7 把产品推进为可长期扩展的教学系统：50 天逐日课程、教学化界面、内容来源可追溯。

V1.7.1 增加主页用户手册和更明确的连续学习存储体验，包括写作/应用草稿自动保存、最后保存时间和本机存储说明。

V1.7.2 不修改学习内容，重点升级兼容架构：

1. 同一天从 5 小时升级到 6.5 / 8 小时只提高目标配额，不覆盖已经完成的训练记录。
2. 每个 Day 记录自己的起始强度、当前强度、最高强度和强度切换历史。
3. 引入 State Schema 和 additive migration，后续新模块只能增加字段或迁移数据，不能静默重置旧用户进度。
4. 引入按 Content ID 锁定的每日材料分配，后续扩充题库或调整数组顺序不会改变旧用户已经分配的材料。
5. 升级前自动保存安全快照，并在迁移前后检查关键历史学习指标没有减少。
6. 新模块通过统一模块注册接口接入，避免各模块自行改写核心状态。

架构规范见：`docs/compatibility-v172.md`。

## 50 天路线

- Day 1–18：基础与语法自动化。A1+ → A2/A2+，重点是现在时、否定、提问、过去时、未来、代词、关系代词、比较、条件式和连接词的主动调用。
- Day 19–30：应用迁移。叙事、请求、建议、投诉、比较、观点、书面互动、阅读定位和听力策略。
- Day 31–40：DELF B1 四项专项。听力、阅读、写作 ≥160 词、三类口语任务和 Mini-mock。
- Day 41–50：模拟与修复。Mock、错误分类、定向修复、输出速度、Final mock 与考前轻复习。

机器可读课程和教学资产：

- `content/source-catalog-v17.json`
- `v17-pedagogy.js`
- `v171-user-manual.js`
- `v172-compat-architecture.js`

## 每日强度

- 5 小时：语法客观题 8、主动产出 6、应用 2、听力 2、阅读 2、写作 1、口语 2。
- 6.5 小时：语法客观题 10、主动产出 8、应用 3、听力 3、阅读 3、写作 1、口语 3。
- 8 小时：语法客观题 12、主动产出 10、应用 4、听力 4、阅读 4、写作 2、口语 4。

高强度只增加当前阶段的不同材料、重复调用和复盘，不越级引入后续语法。

### 同一天加练逻辑

V1.7.2 将“已经完成多少”和“当前强度要求多少”分开管理。

例如 Day 8 在 5 小时模式已经完成：

- 语法 8
- 应用 2
- 听力 2
- 阅读 2
- 写作 1
- 口语 2

之后切换到 8 小时模式时，以上完成记录保持不变，只把目标提升到：

- 语法 12
- 应用 4
- 听力 4
- 阅读 4
- 写作 2
- 口语 4

系统会继续安排后续未完成内容，而不是覆盖、重置或从头开始。

如果之后再从 8 小时改回 5 小时，已经完成的额外训练同样不会删除。

V1.7.2 新增每 Day 独立的 `dayPlans172`，记录：

- `startedIntensity`
- `currentIntensity`
- `maxIntensityReached`
- `startedTargets`
- `intensityEvents`
- `startedAt`
- `lastActiveAt`
- `completedSnapshot`

在还没有任何学习证据前调整 5 / 6.5 / 8 小时，只视为修改当天计划；真正开始学习后再提高强度，才会记录为一次 `upgrade` 事件。

## 词块与复习计数

V1.7.2 新增 `practiceCounters172`，将之前较粗的词块/复习 Boolean 完成状态升级为数量计数。

例如高强度模式可以真实表达：

- 词块 `25 / 45`
- 复习 `10 / 20`

旧版本中只有 Boolean 的历史记录无法恢复精确数量，因此迁移时采用保守原则：已完成最多只推定为旧 5 小时最低量，不凭空制造更高训练量。

## 首页用户手册

首次进入主页时用户手册默认展开，解释六个学习步骤：

1. 选择 Day 和每日学习时长。
2. 查看 Can-do 与前置复习。
3. Grammar Gym：规则 → 客观题 → 变形/纠错 → 主动造句 → 情境调用。
4. 应用、听力和阅读：把语法迁移到真实任务与输入理解。
5. 写作和口语：建立连续输出，Day 31+ 进入正式 DELF 任务强度。
6. 错题回炉与下一天：形成延迟复习闭环。

用户点击“我已了解”后手册默认折叠，但一直保留在主页，可随时重新展开。

## 自动保存与连续学习

自动保存不是纯 UI 文案，底层学习状态确实通过 `save()` 写入本机浏览器。

会自动保存的操作包括：

- 语法、阅读和听力答题；
- 学习块完成；
- Day 和强度切换；
- 应用任务提交；
- 写作提交；
- 口语任务与录音完成；
- 错题回炉操作；
- 写作和应用输入停止约 650 ms 后自动保存草稿。

主页会显示：

- 尚未开始：`第一次答题、输入或录音后自动保存`；
- 已开始：`已自动保存 · Day X · 最后保存时间 · 本机浏览器`。

存储边界：

- `localStorage`：学习状态、答题、进度、写作/应用文本记录和草稿。
- `IndexedDB`：口语录音文件。
- JSON 导出/导入：学习状态备份与迁移；不包含录音文件。
- 当前版本尚未提供云端账号同步。清除站点数据或换设备可能丢失本机数据，因此建议每周导出一次 JSON 备份。

V1.7.2 沿用现有学习数据 key，不主动清空用户历史进度。

## State Schema 2 与迁移规则

V1.7.2 正式引入 `State Schema = 2`。

迁移原则是 additive migration：

- 可以新增字段；
- 可以补充旧数据缺少的结构；
- 可以为旧记录补 Content ID；
- 不允许静默删除旧记录；
- 不允许因为新模块上线而重算或清空已有学习证据。

第一次从旧 Schema 升级到 Schema 2 时，会尝试在 `localStorage` 中保存迁移前安全快照：

`delf50_safety_snapshot_pre_schema2`

迁移前后会保护以下关键历史指标：

- `selectedDay`
- 语法 attempts / correct
- 阅读 attempts / correct
- 听力 attempts / correct
- 应用完成数和记录数
- 写作完成数和记录数
- 口语完成数、记录数和累计时长
- 错题数量
- 历史任务完成数量

如果 migration 导致上述受保护指标变化，兼容层会将该迁移视为失败，而不是继续覆盖用户状态。

迁移历史保存在：

`S.meta172.migrations`

## Content ID 与题库扩展保护

V1.7 已经为教学内容建立稳定 `traceId`；V1.7.2 在此基础上进一步引入按 Content ID 锁定的每日分配：

`S.assignments172`

这解决了旧结构中“下一篇材料依赖数组位置”的问题。

例如某个 Day 已经分配：

`READ-r16-01`

以后即使在题库最前方增加 100 篇新阅读，系统仍然优先按这个 ID 找回原材料，而不是因为数组顺序变化改成另一篇。

已有 Content ID 的长期规则：

- 不改名；
- 不复用；
- 不用一个旧 ID 替换成完全不同的内容；
- 新内容优先 append；
- 如需修正内容错误，应保留 ID，并记录 revision / change history。

当前审计范围包括语法节点和题目、阅读/听力材料及问题、写作、口语和应用任务。

当前已建立：

- provenance / traceId：464 个；
- 可用于材料分配的内容 ID：120 个；
- 缺失：0；
- 重复：0。

## 新模块扩展规则

未来增加词汇、听写、Shadowing、AI 写作、AI 口语、SRS、Mock Exam 等模块时，应使用独立字段，例如：

- `S.dictationV1`
- `S.shadowingV1`
- `S.mockExamV1`

不得直接修改已有核心字段的含义。

V1.7.2 暴露统一架构入口：

`window.DELF50_ARCH`

其中包含：

- `registerModule()`：注册新模块版本和 migration；
- `report()`：查看当前兼容状态；
- `changeIntensity()`：按兼容规则改变当日强度；
- `getDayPlan()`：读取 Day 独立计划；
- `getAssignments()`：读取当前 Day 的 Content ID 分配；
- `resolveAssignedContent()`：按 ID 解析材料；
- `contentAudit()`：检查内容 ID 和追溯状态。

新模块注册时，兼容层会在 migration 前后比较受保护的旧学习指标。如果某模块导致历史学习记录减少，则该模块 migration 失败。

## 来源与可追溯性

每个内容项拥有稳定 `traceId`，例如：

- `GQ-present-01`：语法题
- `READ-r16-01`：阅读篇章
- `RQ-r16-01-1`：阅读问题
- `LIST-l16-01` / `LQ-l16-01-1`：听力脚本及问题
- `WRITE-*` / `SPEAK-*` / `APP-*`：写作、口语和应用任务

`provenance` 包含 `traceId / kind / author / basis / extension / note`。DELF50 自编题明确标记为原创训练材料，不冒充 France Éducation international 官方真题。

来源原则：

- France Éducation international：DELF B1 考试结构、样题格式、评分与备考要求。
- Council of Europe CEFR：B1 Can-do、reception / production / interaction 和行动导向课程设计。
- Académie française：规范法语和词义查证。
- RFI / TV5MONDE：拓展学习链接，不复制其受版权保护内容。

更完整的内容规范见 `docs/content-model.md`。

## 进度评估原则

初始化为 0 / 未评估。

- 语法 / 阅读 / 听力：只用真实客观题样本计算正确率。
- 写作：记录文本、字数、结构与完成次数；未接可靠评分器前不伪造 DELF 分数。
- 口语：记录录音、训练时长、任务次数和回听证据；未接可靠法语 ASR + DELF 评分器前不生成口语水平百分比。
- 提前进入未来 Day 不会自动补齐过去 Day，也不会提升能力指标。
- 强度升级只改变目标，不重算已完成的能力证据。

## 兼容发布原则

以后发布流程应遵循：

1. 保留当前生产版本作为基线；
2. 新模块使用独立字段；
3. 对旧用户 State 执行 migration；
4. 比较 protected legacy invariants；
5. 验证已有 Content ID 没有缺失、重名或复用；
6. Preview 验证；
7. Production 发布；
8. 检查 runtime 500；
9. 保持学习数据 key 和 IndexedDB 录音存储兼容。

长期原则：

**学习历史属于用户数据层；教学内容属于内容层；新功能属于模块层。升级任何一层，都不应要求用户重新开始学习。**
